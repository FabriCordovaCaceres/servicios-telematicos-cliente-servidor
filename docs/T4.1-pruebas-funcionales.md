## 1. Objetivo

Verificar el funcionamiento del prototipo Cliente-Servidor mediante pruebas funcionales sobre las operaciones de creación, consulta, actualización y eliminación de tareas, incluyendo la validación de datos incorrectos y la sincronización de eventos mediante WebSocket.

## 2. Entorno de pruebas

- Lenguaje: TypeScript y JavaScript.
- Entorno de ejecución: Node.js.
- Framework del servidor: Express.
- Protocolo REST: HTTP.
- Comunicación en tiempo real: WebSocket.
- Servidor REST: `http://localhost:3000/tasks`.
- Servidor WebSocket: `ws://localhost:3000/ws`.
- Herramientas: VS Code, PowerShell y Node.js Test Runner.

Las pruebas se realizaron sobre el servidor ejecutado localmente.

## 5. Revisión del flujo de eliminación

Durante la revisión funcional se analizó con detalle el flujo de eliminación de tareas:

- **Ruta DELETE:** se verificó que la ruta comprueba el resultado de `deleteTask()` y responde 204 si la tarea existía o 404 si no existía.
- **Servicio:** la función `deleteTask()` se reorganizó para que sea más legible (búsqueda de la tarea, obtención de su posición y `tasks.splice(index, 1)`), sin cambiar su comportamiento. La eliminación del arreglo en memoria ya existía desde el Sprint 1.

Las pruebas PF-CS-10 y PF-CS-11 confirman que una tarea eliminada deja de aparecer en la lista y que su consulta devuelve HTTP 404.

**Corrección posterior (T4.6):** las pruebas de seguridad detectaron que se aceptaba un título compuesto solo de espacios. Se corrigió la validación de `POST /tasks` y `PUT /tasks/:id` para responder HTTP 400 en ese caso.

## 6. Ejecución de las pruebas

Con el servidor iniciado mediante:

`npm run dev`

Se ejecutaron los siguientes comandos desde la raíz del repositorio:

**Pruebas REST:**

`node --test ./pruebas/t4.1-rest.test.mjs`

**Pruebas WebSocket:**

`node ./pruebas/t4.1-websocket.mjs`

También se verificó el proyecto mediante:

`npm run lint`

`npm run build`

Ambos comandos finalizaron sin errores en las verificaciones realizadas.

**Ejecución contra la VM (entorno virtualizado):** la variable `CS_URL` indica la dirección del servidor. En PowerShell:

`$env:CS_URL="http://192.168.56.11:3000"; npm test`

Si `CS_URL` no se define, las pruebas usan `http://localhost:3000`.
